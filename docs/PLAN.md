# 독립 프로젝트 개발 계획

## 원칙

- `unified-kanban`은 유지하고 코드·DB·서비스·설정을 변경하지 않는다.
- 이 저장소는 Hermes 코드·배포 bundle·계정·실행 명령에 의존하지 않는다.
- UI는 독립 실행한다. 에이전트가 꺼져 있어도 작업 기록을 조회한다.
- 실제 완료 여부와 사용량을 추정하지 않는다.

## 1차 기반 (구현됨)

Python 표준 라이브러리 HTTP 서버 / SQLite / HTML·CSS·JavaScript UI.
프로젝트 등록, 카드 생성·조회·검색·보관과 명시적 Codex·Claude CLI 래퍼.
영구 카드 UUID, 요청·결과·원본 사용량·세션 ID·시각을 별도 필드로 보관한다.
래퍼가 UI 서버와 독립적으로 DB에 기록하여 UI 장애가 실행 결과를 유실시키지 않게 한다.

## 2차: 평소 사용 경로 자동 수집

1. 실제 사용하는 Codex·Claude 실행 경로와 hook 버전을 확인한다.
2. 기존 사용자 hook을 보존하는 선택 설치/해제 기능을 만든다.
3. 세션·턴 ID를 기반으로 시작/완료 이벤트를 멱등 처리한다.
4. 중복·역순·지연 이벤트, 동시 작업, 재시작·강제 종료 복구를 검증한다.
5. 입력 대기 상태, 관측된 실제 모델, 일자별 사용량을 확인 가능한 범위에서 추가한다.

대화형 세션 수집이 완료되기 전에는 CLI 래퍼 외 경로를 지원한다고 표시하지 않는다.

## 3차: 선택적 기존 기록 이전

기존 프로젝트의 DB를 읽기 전용으로 조사하고 내보내기 파일을 통해 가져온다.
보드·Codex·Claude 기록만 선택 가능하게 하고 원본 ID 매핑으로 중복을 방지한다.
가져오기 미리보기·건수 검증·롤백을 먼저 구현하며 기존 DB는 수정하지 않는다.
새 프로젝트는 데이터 이전 없이도 사용 가능하다.

## 4차: Obsidian 선택 저장

- Done 카드에서 사용자가 필요한 결과만 선택한다. 자동 전체 동기화는 하지 않는다.
- Vault와 하위 폴더를 지정하고 제목·본문·태그를 미리 확인한다.
- Markdown에 카드 ID, 프로젝트, 도구, 완료 시각, 요청과 결과를 기록한다.
- export 기록에 카드 ID, 파일 경로, 저장 시각, 본문 hash를 보관한다.
- 같은 카드의 재저장은 업데이트/새 사본을 선택하고 사용자 수정본을 무단 덮어쓰지 않는다.
- Vault 경로 이탈, 파일명 충돌, 존재하지 않는 폴더, 쓰기 실패와 재시도를 검증한다.

## 완료 기준

Hermes가 없는 환경에서 설치·UI 실행·보드 생성·두 도구의 작업 기록이 가능할 것.
기존 프로젝트 변경이 없을 것. UI/프로세스 재시작 후 데이터가 유지될 것.
각 단계의 미지원 실행 경로와 검증 범위를 README에 정확하게 기록할 것.
